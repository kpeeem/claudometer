Короткий вывод

  • Расширение не ходит на /api/oauth/usage само. В extension.js и webview/index.js такой строки нет ни разу. Из /api/oauth/* оно трогает только /api/oauth/profile (UUID организации) и обновление токена.
  • Все числа ему отдаёт дочерний процесс claude (тот же бинарь 2.1.314 из resources/native-binary/claude). Путь первый: события rate_limit_event, собранные из заголовков anthropic-ratelimit-unified-* в обычных ответах /v1/messages. Они приходят на каждый запрос и ничего не стоят. Путь второй: управляющий запрос get_usage — на первом запуске панели, при входе и при смене аккаунта.
  • Таймера нет. Ни в расширении, ни в webview ни один setInterval не относится к квотам. Обновление идёт по событиям.
  • От 429 его защищает не отсутствие эндпоинта, а редкость обращений и дисциплина внутри CLI: снимок на 60 с, один запрос в полёте, таймаут 5 с, память о 429 на токен (retry-after или 5 минут, потолок 1 час), запасной ответ из заголовков или из сохранённого снимка.
  • Токен общий с CLI. Расширение читает и обновляет тот же элемент Keychain Claude Code-credentials. Своего ключа у него нет.
  • Файла «для чужих» расширение не пишет и не читает. Единственный дисковый кэш — ключ cachedUsageUtilization в ~/.claude.json, и на этой машине его нет.
  • Готовый локальный файл на этом Mac есть, но он не от расширения: ~/Library/Application Support/Agent Meter/claude-usage.json. Его каждые 5 минут обновляет Agent Meter под отдельным входом, с временем сброса. Плате надо брать числа оттуда по BLE, а не опрашивать эндпоинт токеном Claude Code. Подробности в разделе «Что делать плате».
  • Без сети вообще: мод с хуком session.measure внутри каждого запущенного claude получает те же числа из заголовков, что и VS Code, и может писать их в файл. Раздел «Чтение из запущенного Claude без сети».

Схема потока

Расширение — тонкая оболочка над CLI. Всё, что связано с квотами, происходит в процессе claude; расширение только пересылает результат в панель.

1. Прямой вызов эндпоинта или нет

В обоих бандлах расширения нет строки oauth/usage. В extension.js из api/oauth встречаются таблица адресов (create_api_key, roles, адреса авторизации) и один живой запрос — /api/oauth/profile.

Дальше расширение работает так. Процесс claude запускается через Agent SDK (в логах расширения строки «Spawning Claude with SDK query function»). Из его потока расширение ловит сообщения rate_limit_event и пересылает окна в webview. Те же сообщения webview разбирает и сам.

Второй вход — явный запрос чисел у процесса. Метод SDK называется usage_EXPERIMENTAL_MAY_CHANGE_DO_NOT_RELY_ON_THIS_API_YET и уходит процессу как управляющий запрос get_usage. Ответ содержит rate_limits и rate_limits_available.

Что при этом делает сам процесс, видно уже в бинаре. Там есть и чтение эндпоинта, и более дешёвый путь через заголовки. Адреса чтения:

Заголовки, из которых процесс собирает окна без отдельного запроса:

ЗаголовокЧто в нём

anthropic-ratelimit-unified-7d-utilization, -7d-reset, -7d-statusнедельное окно: то же самое
anthropic-ratelimit-unified-representative-claim, -status, -resetкакое окно сейчас ограничивающее

Кроме обычных ответов, при старте сессии процесс делает фоновый пробный запрос на один токен. Из его ответа он тоже берёт заголовки.

2. Опрос: интервал и триггеры

Интервала нет. Я просмотрел все вызовы setInterval: 9 в extension.js и 12 в webview/index.js. В расширении это очистка хранилища, ожидание условия через 100 мс (два места), пересканирование реестра сессий, тик «живости», keepalive и проверка тишины голосового ввода, автоархивация, проверка пропавших вкладок. В webview — детектор утечек слушателей (только отладка), таймер-обёртка VS Code, проверка простоя воркеров Monaco (три места), анимация счётчика токенов (100 мс), опрос статуса MCP-серверов раз в 2 с на экране переподключения, перерисовка относительного времени раз в минуту и четыре спиннера. К квотам не относится ни один.

Обновление чисел запускают пять событий:

Вывод для платы: у расширения «частое обновление» получается не из частых запросов за лимитами, а из того, что каждый ответ модели несёт числа в заголовках. Если в VS Code никто не работает, индикатор не обновляется, и это нормально: использование растёт только вместе с запросами. Исключение — расход с другого устройства или с claude.ai, он появится в заголовках только при следующем запросе здесь.

3. Что с 429

Расширение к 429 по /api/oauth/usage почти не приближается: в просмотренных логах (с 12 по 16 ноября) вообще три запроса к этому эндпоинту (см. «Что видно на этой машине»). А тот, что делает CLI, защищён несколькими слоями. Все константы лежат рядом:

Запоминание ответа. Для 429 и 403 срок равен retry-after, а если его нет или он ноль — 5 минут (Ct); верхний предел 1 час ($e). Для отклонённой авторизации — 1 час (Pt). Пока срок не вышел, функция fe не делает HTTP-запрос, а бросает RememberedResponseError («replayed»).

Цепочка чтения целиком. Для подписки claude.ai с правом profile сначала пробуется снимок моложе 60 с — тогда ответ без сети. Потом идёт эндпоинт. Любая ошибка (в том числе 429) ведёт к запасному ответу со статусом seeded и полем heldUntilMs.

Дедупликация: параллельные чтения одного вида делят один запрос (Wt/pending), а 401 во время чужого обновления токена ждёт его и повторяет запрос один раз. Всё это включено флагом tengu_federated_robin (по умолчанию true); при выключенном флаге память ответов очищается (he.clear()).

4. Кэш на диске

Дисковый кэш один: ключ cachedUsageUtilization в глобальном конфиге CLI. Это ~/.claude.json, а при заданном CLAUDE_CONFIG_DIR — $CLAUDE_CONFIG_DIR/.claude.json. Ниже константы и три функции. Снимок свежий 60 с (it), как запасной годится до 1 часа (on). Запись происходит только после успешного ответа эндпоинта и не чаще раза в it. Если accountUuid снимка не совпадает с текущим аккаунтом, ключ стирается. Снимок игнорируется, если после него уже пришли более свежие заголовки (lastAppliedObservationAtMs).

Форма значения взята из схемы валидации в бинаре. На этой машине ключа нет ни в ~/.claude.json, ни в ~/.claude/.claude.json, поэтому пример иллюстративный: значения выдуманы, идентификатор убран.

Есть ещё кэш в памяти процесса — числа из заголовков (rawUtilization). Снаружи его можно увидеть только через statusLine: команда получает на stdin JSON, в котором rate_limits собран из этого хранилища, а окна с уже прошедшим resets_at отбрасываются.

Форма этого блока:

resets_at здесь — секунды Unix. Блок присутствует, только если хоть одно окно известно.

5. Токен

Расширение хранит и читает учётные данные тем же способом, что и CLI. Имя элемента Keychain — Claude Code + суффикс сборки + -credentials, и если задан CLAUDE_CONFIG_DIR, к имени добавляется - и первые 8 символов SHA-256 от пути этого каталога. В обычной настройке получается Claude Code-credentials.

Обновляет токен тоже само расширение. Ниже кусок после обмена refresh-токена: новый refreshToken берётся из ответа, если сервер его прислал, и записывается обратно. Если сохранённый вход тем временем поменялся, результат помечается superseded.

Что это значит для платы.

  • Лимит /api/oauth/usage, как сообщают в issues, считается на access-токен. Токен у расширения, CLI и платы в режиме «Fetch on board» один и тот же, значит и бюджет запросов общий.
  • Плата в резервном режиме держит копию refresh-токена Claude Code и сама его обновляет. Сервер может прислать новый refresh-токен (i.refresh_token||t в коде выше), поэтому плата и Claude Code могут вытеснять друг друга из входа. Расширение такой случай обрабатывает (superseded), а плата о нём не узнает.
  • Адрес обновления в текущей сборке — platform.claude.com/v1/oauth/token. В README платы указан console.anthropic.com/v1/oauth/token; стоит сверить, тот ли это хост.

Что делать плате

Рекомендация

Убрать опрос эндпоинта токеном Claude Code из основного пути. Плата берёт числа от Mac по BLE, а Mac берёт их из файла, который уже поддерживает Agent Meter. Прямой GET остаётся запасным путём, но с отдельным входом и с правилами CLI.

1. Основной путь: числа от Mac

В README платы так и задумано: Mac уже собирает лимиты и отдаёт их по BLE, плата токенов не держит. Источник на стороне Mac — ~/Library/Application Support/Agent Meter/claude-usage.json. Он обновляется каждые 5 минут под отдельным входом, поэтому не делит бюджет с VS Code и не ломает его вход.

Соответствие полей:

Для платыОткуда в claude-usage.json
5 часов: процент, сбросquotas[window == 300]: used, resetsAt + 978307200
7 дней: процент, сбросquotas[window == 10080]: used, resetsAt + 978307200
Fablefable.used, fable.resetsAt + 978307200
Возраст данныхсейчас минус (quotas[].observedAt + 978307200); не attemptedAt, потому что при ошибке старые числа остаются, а attemptedAt обновляется
Признак «опрос не удался»status != "ready" (для 429 — throttled, плюс retryAt)

2. Как плате показывать устаревшие числа

  • Хранить последнее хорошее значение вместе с моментом наблюдения и показывать возраст. Порог «устарело» — 15 минут при опросе раз в 5.
  • Если время сброса окна уже прошло, число в нём больше недействительно. Сам CLI в этом случае выбрасывает окно (j7/x4e в расширении, ot() в бинаре). Плате лучше показать «ожидание данных» или 0 % с пометкой, чем старые 100 %.
  • Не считать 429 отказом навсегда. Agent Meter откладывает следующую попытку на час (throttleBackoff = 60 * 60), CLI — на retry-after или на 5 минут.

3. Запасной путь: плата ходит сама

Если оставлять режим «Fetch on board», то:

  • Дать плате отдельный вход, а не копию токена Claude Code. Тогда её запросы не расходуют бюджет VS Code и CLI, а её обновление токена не вытесняет их вход. Отдельный вход делается так же, как у Agent Meter: свой CLAUDE_CONFIG_DIR и claude auth login под ним, элемент Keychain получает суффикс с хэшем каталога.
  • Копировать дисциплину CLI. Один запрос в полёте. Результат хранить минимум 60 с. На 429 — ждать retry-after, иначе 5 минут, потолок час, и помнить это на токен. На 401 — одно обновление токена и один повтор. Таймаут 5 с. Заголовок anthropic-beta: oauth-2025-04-20 остаётся.
  • Интервал 20 минут уже мягче, чем у самого CLI, поэтому, если 429 приходит и на нём, причина скорее в том, что токен делит бюджет с кем-то ещё, а не в слишком частом опросе. Это гипотеза: порог на сервере я не измерял. Проверяется просто — переключить плату на отдельный вход и посмотреть, уйдут ли 429.

4. Живые данные без запросов за квотой (по желанию)

Для терминального claude есть бесплатный путь: команда statusLine получает rate_limits из заголовков и может записывать их в файл. Сейчас он у Agent Meter настроен, но файла нет, потому что в панели VS Code эта команда не запускается (см. выше). Поэтому для работы только из VS Code он не поможет; в терминале — поможет.

5. Чего не делать

  • Не вызывать /api/oauth/usage токеном Claude Code по таймеру из нескольких мест одновременно.
  • Не обновлять refresh-токен Claude Code из платы или из любого другого процесса, пока им пользуются CLI и расширение.
  • Не читать plan-usage-history.json как единственный источник: в нём нет времён сброса, и он перестаёт обновляться, когда Claude Desktop закрыт.

Чтение из уже запущенного Claude без сети

Вопрос: можно ли не запускать свой процесс и не ходить в сеть, а брать числа у того claude, который и так работает (панель VS Code, терминал, вкладка Code в Claude Desktop), так же быстро, как их видит VS Code.

СпособЧто выяснилосьГодится
Подключиться к каналу VS Code ↔ claudeЭто stdin/stdout дочернего процесса, чужие трубы снаружи не открыть.нет
Сокет сессии /tmp/cc-socks/<pid>.sockЕго объявляет каждая сессия в ~/.claude/sessions/<pid>.json (messagingSocketPath). Это входящий ящик для сообщений между сессиями с ключом в файле <pid>.<hash>.key (0600). Запроса «дай состояние» там нет: сообщение становится репликой и запускает ход модели, то есть тратит лимит.нет

Мод с хуком session.measureРаботает внутри каждого процесса claude. Событие приходит после каждого хода и когда окно сдвинулось на целый процент, появилось, ушло или сменился статус лимита. В нём rateLimits — те же числа из заголовков ответа. Мод пишет их в файл через $.fs.write по абсолютному пути. Событие есть и в 2.1.314 (VS Code), и в 2.1.321 (Desktop).да

Как это выглядит в типах движка (файл types/claude-code.d.ts из навыка авторинга модов, сборка 2.1.321):

Схема для платы:

  1. Мод ставится один раз для всего пользователя (локальный marketplace и claude plugin install, либо папка в CLAUDE_CODE_PLUGIN_DIRS в ~/.claude/settings.json). После этого он загружается в каждом claude на этом Mac: в терминале, в панели VS Code и во вкладке Code в Desktop.
  2. На session.start и на каждый session.measure, если окна есть, мод записывает в ~/.claude/quota-live.json окна five_hour и seven_day с percentUsed, resetsAt и временем наблюдения. Запись после каждого хода, а не только при сдвиге процента, нужна, чтобы плата отличала свежие числа от давно не обновлявшихся.
  3. Мост на Mac (Agent Meter или отдельный помощник) следит за файлом и отправляет числа на плату по BLE. Ни одного запроса к /api/oauth/usage.

Проверка на этой машине

Мод quota-live собран и загружен в одной сессии Claude Desktop 2.1.321. После первого же хода он записал ~/.claude/quota-live.json: окно 5 часов 19 %, сброс 2026-11-16 04:50 UTC; неделя 3 %, сброс 2026-11-19 22:00 UTC. Agent Meter, который ходит в эндпоинт, полутора минутами раньше видел 18 % и 3 % с теми же временами сброса. Сейчас мод пишет файл при старте сессии и после каждого хода, если есть хоть одно окно.

Ограничения:

  • Числа обновляются только когда какой-то claude на этом Mac делает запросы. В простое использование и так не растёт, но расход с другого устройства или с claude.ai появится только при следующем запросе здесь. Плата по-прежнему сама гасит окно, когда прошёл resetsAt.
  • В rateLimits только five_hour и seven_day (и spend_limit шлюза). Отдельной недельной квоты Fable там нет; её даёт только эндпоинт, то есть Agent Meter.
  • Сессии Agent Meter под отдельным CLAUDE_CONFIG_DIR мод не загрузят, пока его не поставить и туда. Это и не нужно.
  • Несколько сессий пишут один файл; у всех один аккаунт, так что побеждает самая свежая запись. Читатель должен переживать недописанный JSON и просто перечитывать.

Что не проверено

  • Я не запускал claude и не обращался к эндпоинту: так требовала постановка (только чтение, без токенов). Поведение 429 восстановлено по коду и логам, но не воспроизведено.
  • Серверный порог (сколько запросов на токен до 429) из клиента не виден. Все числа «60 с, 5 с, 5 мин, 1 ч» — клиентские.
  • Имена вроде RM, Dt, U, MGn получены минификацией версии 2.1.314 и изменятся в другой. Надёжнее искать по строкам: fetchUtilization:, cachedUsageUtilization, quota_check.
  • Форма cachedUsageUtilization взята из схемы валидации; реального ключа на этой машине нет.
  • Условия, при которых процесс делает пробный запрос quota_check при старте (флаг tengu_cicada_nap_ms и гейты St(), _e()), минифицированы; смысл гейтов не расшифрован.
  • Что панель VS Code не запускает statusLine — вывод по отсутствию кода и файла.
  • Флаги вроде tengu_federated_robin приходят с сервера; поведение памяти ответов может отличаться у другого аккаунта или после обновления версии.

Как перепроверить

Смещения в цитатах — байтовые, так что их можно проверять утилитами, которые считают байты.

EXT=~/.vscode/extensions/anthropic.claude-code-2.1.314-darwin-arm64

grep -c 'oauth/usage' "$EXT/extension.js" "$EXT/webview/index.js"

grep -b -o 'rate_limit_event' "$EXT/extension.js"

python3 -I - "$EXT/resources/native-binary/claude" <<'EOF'
import sys, mmap
f = open(sys.argv[1], 'rb')
m = mmap.mmap(f.fileno(), 0, access=mmap.ACCESS_READ)
for needle in (b'Ct=300000,$e=3600000,Pt=3600000', b'on=3600000,it=60000', b'source:"quota_check"'):
    i = m.find(needle)
    print(i, m[i:i+120])
EOF

grep -c 'fetchUtilization: GET' ~/Library/Application\ Support/Code/logs/*/window*/exthost/Anthropic.claude-code/Claude\ VSCode.log

Файлы с учётными данными Claude Code и Codex и элемент Keychain я не читал. Все идентификаторы аккаунта и организации в примерах убраны.
